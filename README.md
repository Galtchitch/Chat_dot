# netmon — Telegram-бот мониторинга узлов локальной сети

Бот запускается на машине внутри вашей сети (сервер, мини-ПК, обычный ПК с Windows),
периодически проверяет доступность узлов в нескольких подсетях и присылает в Telegram
сообщения о сбоях. Вне заданного окна уведомления не беспокоят — они копятся и
приходят одной сводкой утром.

## Что умеет

- **Несколько подсетей**: сети описываются в `networks`, узлы группируются по ним в `/status`.
- **Окно уведомлений** (например, `07:00-22:30`): ночью сообщения не отправляются,
  а в начале окна приходит сводка о том, что произошло.
- **Сканирование подсетей**: `/scan` находит живые узлы, `/scan-add` сразу ставит их на мониторинг.
- Проверки трёх типов: **ICMP** (ping), **TCP** (порт открыт), **HTTP** (сервис отвечает).
- Параллельный опрос, свой интервал у каждого узла.
- Защита от «мигания» (`flap_threshold`) и периодические напоминания (`down_repeat_minutes`).
- Состояние в SQLite: после перезапуска бот не рассылает алерты заново.
- Поддержка **своего (локального) сервера Telegram Bot API**, если нет доступа в интернет.

## Установка

Нужен Python 3.9+ (проверялось на 3.9 и 3.12). В Windows Python часто запускается
командой `py`, а не `python`.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux/macOS
source .venv/bin/activate

pip install -r requirements.txt
```

## Настройка

1. Получите токен у [@BotFather](https://t.me/BotFather).
2. Впишите его в `.env`:

   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-ваш-токен
   ```

3. Отредактируйте `config.yaml`. Пример для двух подсетей:

   ```yaml
   notify:
     window: "07:00-22:30"   # уведомления только в этом интервале
     timezone: ""            # пусто — время сервера; или Europe/Moscow

   networks:
     - name: "Сеть 124"
       cidr: 192.168.124.0/24
     - name: "Сеть 147"
       cidr: 192.168.147.0/24

   hosts:
     - name: gw-124
       address: 192.168.124.1
       network: "Сеть 124"
     - name: gw-147
       address: 192.168.147.1
       network: "Сеть 147"
   ```

   Поле `network` можно не указывать — сеть определится по адресу.
   Список узлов необязателен: их можно найти командой `/scan-add`.

## Запуск

```bash
python -m netmon
```

Если команда `python` недоступна, используйте `py -m netmon` или `run.bat`.
Готовое окружение `.venv` уже создано, можно запускать сразу:
`.venv\Scripts\python -m netmon`.

Затем напишите боту `/start` — вы подпишетесь на оповещения. Свой Telegram ID для
`admin_ids` можно узнать командой `/id`.

Полезные команды без Telegram:

```bash
python -m netmon check                      # проверить все узлы из базы
python -m netmon check 192.168.124.1        # проверить конкретный адрес
python -m netmon scan                       # просканировать все сети из config.yaml
python -m netmon scan "Сеть 147"            # просканировать одну сеть по имени
python -m netmon scan 192.168.124.0/24 --add   # найти и добавить узлы в мониторинг
```

## Команды в чате

| Команда | Назначение |
| --- | --- |
| `/status` | Состояние узлов, сгруппировано по сетям |
| `/down` | Только недоступные узлы |
| `/check [имя\|адрес]` | Проверить сейчас (без аргумента — все узлы) |
| `/scan [сеть\|CIDR]` | Найти живые узлы в подсети |
| `/scan-add [сеть\|CIDR]` | Найти и добавить узлы в мониторинг |
| `/add имя адрес [icmp\|tcp\|http] [порт] [интервал]` | Добавить узел |
| `/remove имя` | Удалить узел |
| `/disable имя`, `/enable имя` | Пауза и возобновление проверок |
| `/mute`, `/unmute` | Отключить и включить оповещения в этом чате |
| `/id` | Показать ID чата и пользователя |

Примеры:

```text
/add gw-124 192.168.124.1
/add nas 192.168.147.10 tcp 445
/scan Сеть 147
```

## Окно уведомлений

`notify.window` задаёт интервал (в формате `ЧЧ:ММ-ЧЧ:ММ`), в котором разрешены
оповещения. Всё, что происходит вне интервала:

- состояние узлов **продолжает обновляться** — мониторинг не останавливается;
- сообщения не отправляются, а откладываются;
- в начале окна приходит **сводка**: что происходило ночью и какие узлы недоступны сейчас.

Особенности:

- `window: ""` или `window: "always"` — уведомлять круглосуточно.
- Интервал может пересекать полночь: `"22:30-07:00"`.
- Напоминания о всё ещё недоступных узлах (`down_repeat_minutes`) ночью не копятся,
  чтобы сводка не разрасталась.
- `notify.timezone` задаёт часовой пояс (IANA, например `Europe/Moscow`). Пусто —
  берётся время сервера. В Windows для часовых поясов нужен пакет `tzdata`
  (уже указан в `requirements.txt`).

## Несколько подсетей

- Машина с ботом должна иметь маршрут до всех подсетей (несколько интерфейсов,
  маршрутизация или VPN). Если из одной сети вторая недоступна, узлы в ней будут
  числиться недоступными.
- Сети из `networks` используются для группировки в `/status` и для `/scan`.
- В `hosts` поле `network` необязательно: если его нет, сеть определяется по адресу.

## Работа без доступа в интернет (свой Bot API server)

Обычному боту нужен доступ к `api.telegram.org`. Если сервер изолирован, поднимите
рядом [Telegram Bot API server](https://github.com/tdlib/telegram-bot-api) и укажите
его адрес в `config.yaml`:

```yaml
telegram:
  api_base: "http://192.168.1.10:8081"
```

## Автозапуск

- **Linux (systemd)** — шаблон в `deploy/netmon.service`:

  ```bash
  sudo cp deploy/netmon.service /etc/systemd/system/netmon.service
  sudo systemctl daemon-reload
  sudo systemctl enable --now netmon
  ```

- **Windows (Планировщик заданий)** — запускайте `run.bat` по расписанию
  «При запуске компьютера» или оформите службу через [NSSM](https://nssm.cc/).

## Замечания по проверкам

- **ICMP** использует системную утилиту `ping`, поэтому отдельные привилегии не нужны.
  Если в Windows ping заблокирован брандмауэром, используйте проверку `tcp` по нужному порту.
- Многие узлы не отвечают на ICMP — тогда лучше `tcp`.
- Для `http` адрес можно указать как `host`, `host:port` или полный `http://host/path`.
- Интервал проверки ограничен снизу 5 секундами, чтобы не перегружать сеть.
- Сканирование ограничено `scan.max_hosts` (по умолчанию 4096 адресов) на одну сеть.

## Структура проекта

```text
netmon/
  checks.py     проверки icmp / tcp / http
  monitor.py    цикл мониторинга и машина состояний
  notify.py     рассылка, окно тишины и ночная сводка
  schedule.py   разбор окна уведомлений и часовых поясов
  scan.py       сканирование подсетей
  storage.py    SQLite: узлы, подписчики, отложенные события
  bot.py        команды Telegram и группировка по сетям
  config.py     конфигурация (YAML + .env)
  __main__.py   точка входа: run / check / scan
tests/test_monitor.py   тесты (23 шт.)
```
